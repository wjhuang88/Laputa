# Decision Records

Create an ADR when a technical/product architecture choice affects a Soft constraint, relies on an Assumption, forces a notable tradeoff, or supersedes an existing decision. Routine implementation details do not need ADRs.

Current decisions:

- [ADR-0001 — Embed Talos as the Agent runtime boundary](ADR-0001-talos-runtime-boundary.md)
- [ADR-0002 — Abstract providers by functional capability](ADR-0002-functional-provider-abstraction.md)
- [ADR-0003 — Use an Agent-first consumer interaction model](ADR-0003-agent-first-consumer-interaction.md)

New ADRs must state constraints, reasoning, decision, and reversal trigger. Superseding a decision must link both records.
