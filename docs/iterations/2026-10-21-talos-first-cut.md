## Canonical state boundary

First Cut output is durable editorial truth, not reconstructable analysis cache. C introduces a Laputa-owned `FilmState` with its own schema version and persists it atomically at:

`<project>/.laputa/film.json`

The initial FilmState contains:

- `IntentSpec`: the original request plus a concise human-readable normalized intent, optional target duration and tone tags;
- `StoryPlan`: a concise story summary and ordered semantic beats;
- `Timeline`: ordered scenes selecting imported Assets and, for video, bounded source ranges.

Stable scene/beat identifiers are generated by Laputa rather than asking the model to invent UUIDs. The model-facing commit draft uses simple beat keys and imported Asset IDs; the tool validates and canonicalizes them before persistence.

`FilmState` is intentionally named for the continuing project state rather than `FirstCutState`: later Stories D/F should evolve the same durable state instead of migrating a temporary first-cut file.

## Talos / Tool boundary

Talos remains generic and owns loop, tool execution, events, permission handling, cancellation and session behavior. Laputa owns all Vlog semantics.

C starts with the minimum coarse-grained model-facing surface required for one atomic First Cut:

1. `project.inspect` — read-only project snapshot containing imported Asset context plus available canonical Ready analyses; no raw vendor payloads.
2. `film.commit_first_cut` — validated write that atomically commits Intent + Story + ordered Timeline as one FilmState.

This intentionally does **not** implement every eventual V0.1 tool from the product requirements. `asset.analyze/search`, granular `story.get/update`, and `timeline.get/edit` are added only when later Stories require independent operations. The C write path is atomic so a failed tool call cannot leave a half-written Story or Timeline.

Only the known Laputa domain commit tool may be auto-authorized by the composition layer. C must not globally auto-allow arbitrary Talos write tools.

## Progress boundary

The application must not receive raw model/provider orchestration as its normal progress model. `laputa-agent` translates authoritative Talos session/tool events into a small product-level progress contract:

- Starting;
- Understanding moments;
- Finding the story;
- Building scenes;
- Completed / Failed.

Raw Talos events may remain available internally for diagnostics, but normal app integration consumes the Laputa progress projection.

## Risks and assumptions

- The first FilmState schema must stay deliberately small; transitions, effects, audio mixing, generated artifacts, locks and critic metadata belong to later Stories unless required to keep the initial state valid.
- C assumes fixture media is already analyzed. It does not silently call a remote understanding provider from `project.inspect`.
- Atomic First Cut commit is preferred over multiple model-visible mutation tools because C needs a trustworthy initial state, not partial edit-session semantics.
- `ProjectStore` remains the owner of Story A Project/Asset/understanding state. `FilmStore` is intentionally colocated with the FilmState IR in `laputa-timeline`; introducing another project-storage crate would be architectural churn without current evidence.
- Talos write permission must be scoped to Laputa's known domain mutation, not broad filesystem/process writes.

## Change control

### Film persistence owner

The published plan originally described FilmState persistence as an addition to the existing `ProjectStore` boundary. During implementation, that direction would have introduced a `laputa-media -> laputa-timeline` dependency even though FilmState is editorial/timeline truth rather than media-import state.

The implementation therefore keeps `ProjectStore` unchanged and places `FilmStore` beside the FilmState IR in `laputa-timeline`, still rooted at the same project directory and still writing `.laputa/film.json`. This is a boundary correction, not a product/schema change: `project.json` remains schema v1, no new crate is introduced, and callers compose `ProjectStore` + `FilmStore` at the Agent boundary.
