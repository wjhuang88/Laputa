## 返工顺序与完成标准

### 1. 建立可比较的真实产品工程

准备非私人、许可明确的图片/短视频 fixture：足够填充双列素材栏及六个场景，含已选中场景。必须通过真实 Project/FilmState 进入产品；不得用背景截图、静态示例页替代产品布局。现有设计 JPEG 仅作参考，不冒充独立原始媒体。实施时验证可用素材来源；若缺素材，在记录中明确来源待补，不能把纯色色块冒充最终效果。

记录 commit、OS、窗口/内容区尺寸、缩放、媒体来源及状态；输出对照截图。首次基线保留本次失败截图。

### 2. 校准整体构图

对齐紧凑顶栏、双列素材栏、中央 Stage/播放区/完成摘要、右侧上下文面板和底部六场景缩略卡。先确定主要区域边界、间距和比例，再调整细节；使用 GPUI 布局约束适配窗口。不要以压缩所有控件或无限扩大 Stage 替代还原。

产出可运行产品截图：选中和未选中两种状态；复核与参考图的区域边界差异，逐项记录保留差异及理由。

### 3. 补齐真实缩略图与视觉细节

图片和视频都显示真实缩略图；派生缓存写入项目缓存目录，原文件只读。视频取帧/图片缩放在后台执行，缓存可重建；缺失/损坏素材可恢复，滚动/切换不得阻塞界面，旧任务不能覆盖新状态。

对齐大横向场景缩略图、序号、标题/时长、选中蓝框，以及素材网格、上下文摘要、配色、字重、圆角、分隔线和图标。实现优先复用现有 app/media/render 边界，禁止新增无复用价值的通用 UI 框架。

### 4. 整理产品文案与操作

移除正常用户界面的 F3b、Selection、默认编辑目标等工程说明；用自然文案表达选中范围。保留已经实现的排序、缩短、删除、保留/解除保留及其错误反馈，调整呈现方式以符合设计层级。

设计稿中未实现的导出、自然语言提交、换镜头等不能伪装为可用操作：可以禁用并给简短用户说明，具体差异在验收中列出；不借视觉任务实现 F/G/H 全部业务，也不悄悄删除现有功能。

### 5. 自动化回归与真人复验

- fmt、workspace check/test、all-targets/all-features clippy、桌面编译、既有产品 smoke 和治理检查。
- 缩略图测试覆盖真实 image/video、失败路径、缓存重建、原媒体 hash 不变；为新增异步行为验证状态过期保护。

- 视觉截图：正常参考比例、当前 1440×805 窗口、较窄窗口；包含已选/未选状态、素材较多/横向场景滚动，确认无裁切溢出。具体尺寸随环境记录。

## 风险和约束分类

- Hard：原媒体不变、真实产物有效性、桌面响应性、Selection 行为。
- Soft：现有布局细节可按已批准设计修正；不改变 ADR-0003。
- Assumption：不同窗口尺寸可保持参考构图；通过多尺寸真实截图验证。缩略图与 Stage 资源开销通过实际素材和异步回归验证。
- 验收不以虚构“还原率百分比”或仅编译通过衡量；字体跨平台差异单独记录，不能用来解释结构差异。
